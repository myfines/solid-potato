# 开源方案借鉴与总体修理方向

本项目借鉴以下公开方案的工程思路，不复制其代码：

- `eponce00/tiaopen-mcp`：把 TIA Openness 的项目、块、标签、SCL、编译和 LAD 能力集中为 MCP 工具。
- `bentabol/mcp-retry`：传输断开和读取失败可以重连；写入工具不能盲目重试，必须由调用方保证幂等。
- `opencode-ai/opencode`：长任务保留会话上下文，把工具结果作为下一轮 Agent 输入，并将权限作为显式策略。
- `statecli/mcp-server`：用结构化任务状态、错误分析和可重放记录支持自调试。

## 本项目的落地原则

1. 浏览器只是用户界面；TIA 工程动作必须来自 Agent 的 MCP 工具调用。
2. 每个工具调用都记录 `taskId`、参数摘要、结果、错误和时间；错误必须回到 Agent 上下文。
3. 只读探测可以在连接断开后重连一次；创建、写入、导入、编译、保存等副作用操作必须带幂等键或先读取状态再决定是否重试。
4. 原子工作流失败后，Agent 必须优先修复原子工作流，不得读取旧工程后宣称完成。
5. 只有工具返回真实成功、工程路径、程序块和编译结果时，前端才能显示完成。
6. TIA 项目引用必须先做存活探测；发现已释放对象时清除缓存并尝试重新附着，不能继续使用旧 COM 引用。
7. 任务上下文按用户消息边界压缩，保留最近任务摘要和未完成错误；不能每轮清空，也不能无限堆积原始输出。
8. 进程清理只允许匹配本 Agent 自己启动的包路径；不匹配用户安装的 TIA，也不以清理进程代替修复。

## 当前验证门槛

- 新用户从浏览器输入自然语言任务开始。
- 失败时能看到真实错误，Agent 获得错误并继续修复。
- 不允许把 `projects_close` 后的旧对象当作有效会话。
- 设备名称、CPU 料号、工程目录和备份目录在副作用调用前规范化并记录警告。
- 工程必须有真实 SCL、实例 DB、Main/OB1 LAD，离线编译成功后才算通过。
- 测试失败不得伪造成功；每次修复都要用浏览器重新跑完整流程。
